# M0 architecture decisions

Date: 2026-10-25. Scope: approved M0 foundation only.

1. **Milestone precedence.** Follow the detailed IMPLEMENTATION_PLAN M0/M1 split. The SYSTEM_DESIGN section 19 shorthand lists migrations in M0, but the detailed plan assigns database migrations to M1. M0 has no database, Drizzle, Socket.IO, auth, Polly, or provider configuration.
2. **Workspace.** Use the prescribed apps/mobile, apps/server, packages/contracts, packages/config layout. pnpm workspaces and scripts suffice; no additional task orchestrator. Contracts export compiled ESM/declarations, built before their consumers. Development watches contracts. Public schemas never import server internals.
3. **Stable compatible toolchain.** Node 24.13.0, pnpm 12.15.0, Expo 58.0.19, RN 0.88.0, React 19.3.0, Fastify 5.12.7, Zod 4.6.7. TypeScript 6.0.3 matches Expo SDK 58 and is selected within typescript-eslint's supported range (<6.1); latest TypeScript 7 is not used. ESLint 10.13.0 replaces the installer-reported deprecated 9.39.1 line. Direct versions and lockfile are pinned; only required dependency install scripts are allowed.
4. **Test runners.** Vitest tests contracts and Fastify via injection. Jest/jest-expo plus React Native Testing Library supplement it for native component rendering and interactions. This is a tooling addition, not a gameplay architecture change.
5. **Preview isolation.** All four development routes load fixtures only inside a compile-time **DEV** branch. Production routes render the unavailable shell. Preview state selectors never infer correctness, schedule a game, or update scores from text input. Optional result statistics are omitted. No canonical answer words, lookup IDs, provider credentials, or audio assets exist in the preview.
6. **Mockup corrections.** Quick Match General is read-only; friend setup offers five clearly mocked categories. Challenge hides difficulty. Labels are Find Match/Create Invite. Challenge Round 2 uses Level 2. No custom keyboard. Timers and outcomes are labeled presentation fixtures.
7. **Tokens.** Generate typed mobile tokens from the original JSON. CI verifies equality. Keep original approved docs and PNGs unchanged. Use native system fonts and no additional animation; reduced-motion users receive the same static experience.
8. **Health.** Implement only public process liveness at /health/live. Do not report fictitious database readiness. The shared error envelope is sanitized. TanStack Query is used for a manually requested development health check, while local setup controls use React state.
9. **Native validation.** Expo export verifies bundling, not native keyboard behavior or native compilation. Android Expo Go validation is now recorded in M0_VERIFICATION.md; the owner confirmed physical-iPhone launch, visual direction and keyboard-open composer/timer visibility on 2026-10-28. Remaining native iOS navigation, safe-area, accessibility and screenshot evidence is pending; see M0_VERIFICATION.md. Native Android testing required explicit height-based keyboard avoidance and a compact timer pinned above the composer while the keyboard is visible. Other game content stays scrollable on compact screens. These layout corrections preserve the approved keyboard policy without changing gameplay. No production deployment, cloud setup, paid integration, or store release is authorized by this milestone.

## M1 Increment 01 approved decisions — October 29, 2026

The owner approved the coordinated implementation plan; earlier M0 entries remain historical. The detailed M1 plan and approved development policy take precedence over older shorthand about forfeits/current-round-only deduplication.

1. **Pure authoritative core.** Explicit monotonic input time/order and a fixed UTC anchor; no IO, autonomous timers, transport, persistence or random selection. Candidate transitions are not committed outcomes. Increment 02 must serialize receipts and commit atomically before publishing.
2. **Bounded complete attempt history.** Only counted correct/incorrect submissions reserve IDs. Maximum 48 entries across eight rounds; retain every entry, with no eviction. Rejected IDs remain unreserved. Validate match/membership, look up historical counted outcomes, then enforce current-round/window rules for new submissions. Fingerprint exact raw validated text; normalize only for answer comparison.
3. **Ordering and termination.** Drain deadlines through trusted receipt time; do not overtake already-received commands. Exact deadline/grace is closed, and grace wins collisions for ongoing matches. Complete the decisive round and match atomically. Completed results remain completed; unresolved 10-second disconnect interrupts without winner/forfeit.
4. **Atomic protocol and recovery.** Ordered versioned event batches; terminal result/completion share a batch. ACKs carry original match/round/attempt/version. Viewer snapshots include only their counted history, current counters and applicable closed result. Empty batches remain match-context-bound. Private version gaps call for canonical sync, not inference of a game outcome.
5. **Preparation and text.** Clear only unscheduled readiness on disconnect; committed schedules never reset. Keep the existing 120 UTF-16-unit input bound. Match using NFC, trim, locale-independent lowercase, NFC, preserving internal punctuation/space/accents.
6. **Privacy and assets.** Strict public allowlists and detached projections. Opaque audio version/access, measured duration and checksum of reviewed bytes; never spelling hashes, catalog IDs, variants or guessed text. Closed result is the only permitted canonical-spelling reveal. Synthetic server test fixtures are not approved content.
7. **Integration controls.** Lead owns contracts/docs; backend owns implementation/baseline tests; QA owns snapshot/adversarial tests. Separate worktrees, three reviewable commits and integrated quality/Expo/export/CI gates. Preserve all dependency policies and M0 visuals. Pause before Increment 02.
